# 관제 화면

생성 모델과 검증 모델이 실제로 어떤 프롬프트를 주고받고 어떻게 판정하는지 웹 브라우저에서 실시간으로 확인하는 대시보드입니다.

```bash
# PowerShell 간편 실행
.\run_crex_viz.ps1

# 또는 Python 모듈로 직접 실행
python -m crex.viz
```

실행한 뒤 브라우저에서 `http://127.0.0.1:18765`로 접속하면 됩니다.

## 왜 필요한가

MCP 서버는 에이전트 컨텍스트를 아끼기 위해 **지적 요약만** 반환합니다. 일반 사용자에게는 편리하지만, 프롬프트를 다듬거나 특정 오탐이 왜 발생했는지 분석할 때는 파이프라인 내부의 상세 기록이 필요합니다.

- 소스 코드가 어느 함수 경계에서 어떤 청크로 나뉘었는가
- 정적분석 도구가 해당 청크에서 어떤 사실을 보고했는가
- 생성 모델이 **어떤 프롬프트와 AST·흐름 문맥을 받고** 어떤 응답을 생성했는가
- 검증 모델이 각 지적을 **어떤 근거로** 채택하거나 기각했는가

관제 화면의 중심에 단순 결과 표뿐만 아니라 생성·검증 모델의 실시간 호출 레인(Call Lane)을 배치한 이유입니다.

## 화면 구성과 읽는 법

### 상단 헤더

오른쪽 상단에 현재 대상 저장소와 생성·검증 모델 이름이 배지(칩) 형태로 표시됩니다. 배지에 마우스를 올리면 전체 경로와 엔드포인트 주소를 확인할 수 있습니다.

- **`엔드포인트 점검`**: 터미널의 `python -m crex doctor`와 동일한 점검을 웹 화면에서 즉시 실행합니다.
- **`정보`**: 제작자 정보와 현재 실행 중인 CREX 버전을 표시합니다.

### 파이프라인 진행 레일

`청킹 → 그라운딩 → 생성 → 검증` 네 단계가 진행 상황에 따라 차례로 활성화되며, 완료되면 각 단계의 소요 시간이 표시됩니다. 그라운딩 단계가 유독 오래 걸린다면 특정 정적분석기가 타임아웃(기본 120초)까지 실행 중일 가능성이 있습니다.

### 요약 지표

| 지표 항목 | 설명 |
|---|---|
| 청크 | LLM 호출 단위 (대체로 변경된 함수 1개, 최대 150줄) |
| 정적분석 | 정적분석 도구가 보고하여 프롬프트에 주입된 지적 건수 |
| 생성된 지적 | 생성 모델이 1차로 출력한 후보 지적 건수 (검증 전) |
| 결정론적 기각 | LLM 호출 없이 규칙으로 즉시 걸러낸 건수 (라인 범위 초과, 중복, 제외 규칙 등) |
| 검증 기각 | 검증 모델이 근거 부족 또는 오탐으로 기각한 건수 |
| 최종 유지 | 모든 검증을 통과해 최종 리포트에 수록된 건수 |
| 기각률 | 전체 기각 건수 ÷ 생성된 지적 건수 (정상 범위 40~60%) |

기각률이 지나치게 낮으면 검증 모델이 제 역할을 하지 못하고 있다는 신호이며, 반대로 지나치게 높으면 생성 프롬프트나 룰에서 과도한 오탐이 발생하고 있다는 뜻입니다.

### 생성·검증 호출 레인

왼쪽 열이 생성 모델 호출, 오른쪽 열이 검증 모델 호출입니다. 카드 하나가 LLM API 호출 1회에 해당합니다.

**카드를 클릭하면 해당 호출의 모든 상세 내역이 열립니다** — 시스템 프롬프트, 사용자 프롬프트(주입된 AST 계약 및 호출 그래프 슬라이스 포함), 강제된 JSON 스키마, 모델의 응답 원문, 파싱 결과를 모두 볼 수 있습니다.

스키마 탭에서 `line` 필드의 `enum` 목록을 확인해 보십시오. 해당 청크에서 실제로 변경(`added`)된 라인 번호만 허용되어 있어, 라인 번호 환각이 사후 필터링이 아니라 **생성 단계에서 구조적으로 차단되는 원리**를 직접 확인할 수 있습니다.

### 판정 내역 표 및 `.crexignore` 연동

채택(`유지`)된 지적과 탈락(`기각`)한 지적을 한 표에서 비교할 수 있으며, 기각된 항목에는 구체적인 기각 사유가 표시됩니다. 각 지적 행에는 생성 모델이 제시한 **수정 제안 코드**와 검증 모델이 남긴 **검증 코멘트**가 함께 나타납니다.

- **지적 접기/펼치기 및 제외 규칙 등록**:
  - 각 지적 행 우측의 `[+ 제외]` 버튼을 누르면 해당 파일·디렉터리·전역 범위에서 특정 룰(또는 파일 전체)을 `.crexignore`에 바로 등록할 수 있습니다.
  - 이미 `.crexignore`에 의해 제외되는 항목에는 `[제외됨]` 배지와 `[취소]` 버튼이 표시되어 클릭 한 번으로 제외를 되돌릴 수 있습니다.
  - 표 상단 툴바의 `[.crexignore 관리]` 버튼으로 저장소 전체의 제외 규칙을 일괄 조회·추가·삭제할 수 있습니다.

#### CSV 및 HTML 리포트로 저장하기

판정 내역 표 오른쪽 상단의 **`CSV 저장`** 또는 **`HTML 저장`** 버튼을 누르면 파일 이름을 지정하는 모달 창이 열립니다.

- **`HTML 저장`**: 현재 보고 있는 관제 화면의 다크 테마 디자인, 요약 지표, 접기/펼치기 가능한 판정 내역 표를 외부 의존성 없는 단일 `.html` 파일로 내려받습니다.
- **`CSV 저장`**: 현재 선택된 필터 탭(`전체` / `유지` / `기각`)에 해당하는 판정 목록을 `.csv` 파일로 내려받습니다.

CSV 파일에는 오프라인 통계 분석과 룰 튜닝에 필요한 모든 필드가 담깁니다.

| 열 이름 | 수록 내용 |
|---|---|
| `파일`, `라인`, `끝라인` | 지적 대상 파일 경로 및 라인 범위 |
| `심각도`, `차원`, `룰` | `high` / `code_defect` / `cpp.use-after-move` 등 원본 식별자 값 |
| `판정`, `기각사유`, `결정론적기각` | `유지`/`기각` 여부, `line_out_of_range` 등 기각 사유 코드, 결정론적 기각 여부 |
| `내용`, `수정안` | 생성 모델이 작성한 지적 설명 및 수정 코드 제안 |
| `검증사유`, `검증코멘트` | 검증 모델이 작성한 판정 근거 및 코멘트 |
| `청크` | 해당 지적이 생성된 청크 ID |

**Excel에서 바로 열어도 한글이 깨지지 않습니다.** UTF-8 BOM을 포함하여 저장하며, `=`, `+`, `-`, `@`로 시작하는 셀 값 앞에는 작은따옴표(`'`)를 자동으로 붙여 Excel이 코드 조각(예: `= nullptr`, `-1`)을 수식으로 오인해 `#NAME?` 오류를 내는 현상을 방지합니다.

### 에이전트가 받는 요약

Zed 에이전트 패널에 실제로 반환되는 요약 문자열 그대로입니다(`ReviewService`의 실제 반환값).

## 실행 기록은 로컬 SQLite DB에 안전하게 보관됩니다

모든 실행 이력은 워크스페이스 내부의 `<워크스페이스>/.crex/viz.db` 파일에 자동으로 저장됩니다. Python 표준 라이브러리인 `sqlite3`만 사용하므로 **외부 패키지나 별도 DB 서버 없이 폐쇄망에서 100% 동작합니다.**

- **완전한 원본 보존**: 브라우저 `localStorage`의 5MB 용량 제한이나 긴 프롬프트 잘림 없이 모든 LLM 입출력 원문과 이벤트 시퀀스가 온전히 보존됩니다.
- **개별 실행 삭제**: 왼쪽 "지난 실행" 목록에서 각 항목 우측의 `✕` 버튼을 눌러 원하는 실행 기록만 선택적으로 삭제할 수 있습니다.
- **전체 비우기**: "기록 비우기" 버튼으로 저장된 실행 이력을 한 번에 정리할 수 있습니다.

## 실행 옵션

```bash
python -m crex.viz --port 9000 --workspace D:\work\myproject --config crex.json
```

| 옵션 | 설명 | 기본값 |
|---|---|---|
| `--host` | 바인드 주소 | `127.0.0.1` |
| `--port` | 접속 포트 | `18765` |
| `--workspace` | 리뷰 대상 저장소 루트 (`--repo` 별칭 지원) | 현재 디렉터리에서 `.git` 루트 탐색 |
| `--config` | 설정 파일 경로 | 워크스페이스 → 현재 디렉터리 순 탐색 |
| `--out` | 리포트 저장 디렉터리 | `<워크스페이스>/reports` |
| `--stdlib` | `uvicorn`이 설치되어 있어도 표준 `http.server` 사용 | 꺼짐 |

환경변수 `CREX_WORKSPACE`, `CREX_CONFIG`, `CREX_REPORTS`도 CLI 및 MCP 서버와 동일한 우선순위로 인식합니다 ([설정 문서](configuration.md#workspace--리뷰-대상-저장소) 참고).

### 화면에서 대상 저장소 바꾸기

왼쪽 패널의 "워크스페이스" 옆 **변경** 버튼을 누르면 디렉터리 브라우저 또는 경로 입력을 통해 리뷰 대상 저장소를 즉시 전환할 수 있습니다. 새 저장소 안에 `crex.json`이 있으면 해당 설정을 자동으로 불러옵니다.

**이 변경은 관제 서버가 실행 중인 동안에만 유지되며**, 디스크의 `crex.json`은 수정하지 않습니다. 영구적으로 고정하려면 `python -m crex workspace <경로>` 명령을 사용하십시오.

다음 두 경우에는 보안을 위해 워크스페이스 변경을 거부합니다.

- **리뷰가 실행 중일 때**: 실행 도중 대상 저장소가 바뀌면 서로 다른 저장소의 결과가 한 리포트에 섞이므로, 완료 후 변경하거나 실행을 먼저 중단해야 합니다.
- **루프백(`127.0.0.1`)이 아닌 주소로 바인딩한 경우**: 관제 화면에는 별도 로그인 인증이 없으므로, 외부 접속이 가능한 상태(`--host 0.0.0.0` 등)에서는 서버의 임의 디렉터리 탐색 및 워크스페이스 변경을 차단(`403 Forbidden`)합니다.

### C++ compile_commands.json 만들기

왼쪽의 **compile_commands.json** 패널을 펼치면 터미널로 나가지 않고 웹 화면에서 바로 컴파일 DB를 생성할 수 있습니다.

1. 워크스페이스를 `.sln`, `.vcxproj`, 또는 `CMakeLists.txt`가 위치한 저장소로 맞춥니다. **빌드 대상** 줄에 자동 감지된 프로젝트가 표시되며, 후보가 여러 개이면 드롭다운에서 직접 선택할 수 있습니다.
2. 구성(`Debug`/`Release`), 플랫폼(`x64`/`Win32`), 타깃(`Rebuild`)을 확인합니다. 기본 타깃이 `Rebuild`인 이유는 증분 빌드를 사용하면 이미 빌드된 파일이 컴파일 이벤트에서 누락되어 불완전한 DB가 만들어지기 때문입니다.
3. **생성 시작**을 누르면 실시간 빌드 로그가 화면에 스트리밍되며, 전체 로그는 `.crex/compiledb/msbuild.log`에 저장됩니다.

생성이 완료되면 **현재 실행 중인 설정에 즉시 반영**되어 다음 리뷰부터 `clang-tidy`가 해당 DB를 사용합니다. `crex.json에도 적기` 옵션이 켜져 있으면(기본값) 설정 파일의 `compile_commands_dir`에도 경로가 저장됩니다.

## `uvicorn`이 없어도 동작합니다

`uvicorn`이 설치되어 있으면 ASGI 서버로 기동하고, 없으면 Python 표준 라이브러리인 `http.server`(`ThreadingHTTPServer`)로 자동 폴백합니다. 기능과 화면 동작은 100% 동일합니다.

## LLM 서버 없이 화면 동작 확인하기

폐쇄망 반입 직후 아직 vLLM 서버가 준비되지 않았을 때는 `tests/fake_vllm.py`를 이용해 실제 LLM 없이도 관제 화면의 전체 동작을 점검할 수 있습니다.

## 자주 겪는 증상

- **화면은 열리는데 리뷰 실행이 즉시 실패합니다**: 상단의 `엔드포인트 점검`을 눌러 보십시오. 모델 배지가 붉게 표시되면 vLLM 서버가 꺼져 있거나 모델 이름이 일치하지 않는 것입니다.
- **청크가 0개로 나옵니다**: 변경된 파일 중 지원 언어(`.cpp`, `.cs`, `.py` 등)가 없거나, 제외 규칙(`.crexignore`)에 의해 모두 제외되었거나, diff와 디스크 파일이 일치하지 않아 건너뛴 경우입니다.
- **중단 버튼을 눌렀는데 즉시 멈추지 않습니다**: 이미 vLLM 서버로 전송된 요청은 응답이 돌아올 때까지 대기하며, 그다음 청크 호출부터 중단됩니다. 중단된 실행도 그때까지 완료된 결과로 리포트를 생성합니다.
