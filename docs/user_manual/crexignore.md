# 리뷰 대상 제외 (.crexignore)

리뷰 대상 저장소에서 특정 파일·디렉터리를 제외하거나, 불필요한 룰(또는 특정 경로에 한정한 룰)을 리뷰에서 제외하는 방법을 설명합니다.

저장소 루트에 `.crexignore` 파일을 두면 코드 리뷰 시 검사하지 않을 파일 경로와 제외할 룰을 선언할 수 있습니다.

---

## 언제 쓰나

1. **외부 라이브러리 및 자동 생성 코드 제외**: `vendor/`, `third_party/`, Protobuf 생성 코드(`*.pb.cc`) 등 사람이 직접 작성하지 않은 코드를 건너뛰어 LLM 토큰 비용과 리뷰 시간을 절약합니다.
2. **테스트·문서 코드에서 특정 룰 제외**: 테스트 코드(`tests/**`)에서는 매직 넘버 검사(`any.magic-number`)나 엄격한 예외 처리 룰이 불필요할 수 있습니다. 이럴 때 해당 디렉터리에 한해서만 특정 룰을 비활성화합니다.
3. **팀 정책과 맞지 않는 룰 전역 제외**: 특정 룰이 프로젝트 코딩 표준과 맞지 않거나 오탐이 잦은 경우, 저장소 전체에서 해당 룰을 끕니다.
4. **저장소별 독립적인 제외 규칙 공유**: `crex.json` 설정을 건드리지 않고 대상 저장소 자체에 `.crexignore`를 커밋해 두면, 저장소를 리뷰하는 모든 팀원에게 동일한 제외 규칙이 자동으로 적용됩니다.

---

## 파일 위치와 기본 형식

`.crexignore` 파일은 **리뷰 대상 저장소(워크스페이스)의 루트 디렉터리**(`.git` 폴더가 위치한 곳)에 생성합니다.

- 한 줄에 하나의 패턴을 작성합니다.
- `#`으로 시작하는 줄은 주석으로 처리됩니다.
- 빈 줄이나 공백만 있는 줄은 무시됩니다.
- Windows와 Linux 환경 모두 경로 구분자로 슬래시(`/`)를 사용하십시오.

---

## 1. 파일 및 디렉터리 제외

파일이나 디렉터리 경로의 glob 패턴을 적으면, 해당 파일은 리뷰 파이프라인의 시작 단계에서 완전히 제외됩니다.

```gitignore
# 특정 디렉터리 전체 제외
build/
dist/**
third_party/**
vendor/**

# 특정 확장자나 자동 생성 코드 제외
*.pb.h
*.pb.cc
*.min.js
*.generated.cs

# 특정 단일 파일 제외
src/legacy/old_parser.cpp
```

### 동작 방식

- **토큰 비용 절감**: 제외된 파일은 diff 수집 및 청킹(chunking) 단계에서 즉시 걸러지므로 LLM 컨텍스트로 전달되지 않습니다.
- **정적분석 시간 단축**: 외부 라이브러리나 빌드 산출물에 대해 불필요한 정적분석기 실행을 방지합니다.
- **경로 매칭 규칙**: 모든 경로는 저장소 루트 기준의 상대 경로입니다. 하위 디렉터리를 모두 포함하려면 `디렉터리/**` 형식을 권장합니다.

---

## 2. 전역 룰 제외 (`rule:<룰패턴>`)

특정 룰 ID 또는 와일드카드 패턴 앞에 `rule:` 접두어를 붙이면, 저장소의 모든 파일에서 해당 룰이 리뷰 대상에서 제외됩니다.

```gitignore
# C 스타일 캐스트 룰 전역 제외
rule:cpp.c-style-cast

# C++ 관련 모든 룰 제외
rule:cpp.*

# 매직 넘버 검사 룰 제외
rule:any.magic-number
```

### 동작 원리

1. **생성 모델(Generator) 스키마 제외**: 리뷰 청크를 모델에 전달할 때 프롬프트와 JSON 스키마(`enum`)에서 해당 룰이 사전에 제거됩니다.
2. **필터 단계 결정론적 기각**: 생성 모델이 혹시 해당 룰로 지적을 생성하더라도, 필터(`ReviewFilter`) 단계에서 결정론적으로 즉시 기각(`RULE_EXCLUDED`)되며 검증 모델(`Verifier`)을 호출하지 않습니다.

---

## 3. 특정 경로에 한정한 룰 제외

특정 디렉터리나 파일에서만 특정 룰을 끄고, 나머지 소스 코드에서는 정상적으로 검사하고 싶을 때 사용합니다. 아래 세 가지 표기법을 모두 지원합니다.

### 문법 1: 콜론(`:`) 구분

`<경로패턴>:<룰패턴>`

```gitignore
# src/legacy 하위에서는 C++ 관련 모든 룰 제외
src/legacy/**:cpp.*

# tests 하위에서는 매직 넘버 룰 제외
tests/**:any.magic-number
```

### 문법 2: 공백 및 `rule:` 접두어

`<경로패턴> rule:<룰패턴>`

```gitignore
# tests 하위에서는 매직 넘버 룰 제외
tests/** rule:any.magic-number

# vendor 하위에서는 보안 관련 룰 제외
vendor/** rule:security.*
```

### 문법 3: 콜론 및 `rule:` 접두어

`<경로패턴>:rule:<룰패턴>`

```gitignore
# src/parser 디렉터리에서는 포인터 무효화 룰 제외
src/parser/*:rule:cpp.dangling-*
```

### 동작 방식

- 패턴과 일치하는 파일(예: `tests/test_calc.py`)을 리뷰할 때는 `any.magic-number` 룰이 프롬프트에서 빠지고 필터에서도 기각됩니다.
- 패턴과 일치하지 않는 일반 파일(예: `src/calc.py`)을 리뷰할 때는 해당 룰이 정상적으로 적용됩니다.

---

## 4. `crex.json` 설정과의 관계

`.crexignore`와 `crex.json`의 제외 설정은 어느 한쪽이 다른 쪽을 덮어쓰지 않고 **합산(Union)**되어 함께 적용됩니다.

```json
{
  "review": {
    "exclude": [
      "temp/**"
    ],
    "exclude_rules": [
      "cpp.c-style-cast",
      "src/legacy/**:cpp.*"
    ]
  }
}
```

### 제외 항목의 병합 순서

1. **내장 기본 제외(`DEFAULT_EXCLUDE`)**: `.git`, `.*`, `*.min.js` 등 기본 무시 패턴
2. **`crex.json`의 `exclude` / `exclude_rules`**: 도구 설정 파일에 정의된 공통 패턴
3. **`.crexignore`**: 저장소 루트 파일에 정의된 저장소별 패턴

세 곳 중 어느 하나라도 제외 조건에 매칭되면 리뷰 대상에서 제외됩니다.

| 설정 위치 | 권장 용도 | 장점 |
|---|---|---|
| `.crexignore` | 저장소 루트 (`.git`과 같은 위치) | Git에 커밋되어 팀 전체에 동일한 제외 규칙이 자동 공유됨 |
| `crex.json` | CREX 실행 환경 또는 전역 설정 | 여러 저장소에 공통으로 적용할 인프라·보안 정책 관리에 적합 |

## 작성 예시

저장소 루트에 바로 두고 사용할 수 있는 `.crexignore` 작성 예시입니다.

```gitignore
# ==============================================================================
# .crexignore
# ==============================================================================

# 1. 파일/디렉터리 제외 (토큰 절약 및 스캔 제외)
build/**
dist/**
bin/**
obj/**
third_party/**
vendor/**
*.pb.h
*.pb.cc
*.min.js

# 2. 전역 룰 제외 (프로젝트 전체에서 비활성화)
rule:cpp.c-style-cast

# 3. 경로별 한정 룰 제외 (특정 디렉터리에서만 제외)
# 테스트 코드에서는 매직 넘버 검사 제외
tests/**:any.magic-number

# 레거시 폴더에서는 C++ 관련 룰 전체 제외
src/legacy/**:cpp.*

# 외부 스크립트에서는 Python 룰 제외
scripts/vendor/** rule:python.*
```

## 관제 화면(viz)에서 제외 추가 및 취소

텍스트 편집기로 파일을 직접 열어 수정하지 않아도, `crex.viz` 관제 화면에서 코드 리뷰 결과를 확인하며 곧바로 제외 규칙을 추가하거나 취소할 수 있습니다.

1. **지적 항목에서 바로 제외 추가**:
   - 판정 내역 표의 각 행 오른쪽에 있는 `[+ 제외]` 버튼을 클릭합니다.
   - 팝오버 메뉴에서 제외 범위(이 파일에서만 해당 룰 제외, 상위 폴더에서 해당 룰 제외, 모든 파일에서 해당 룰 제외, 이 파일 전체 제외)를 선택한 뒤 `[제외 등록]`을 누르면 대상 저장소의 `.crexignore`에 즉시 반영됩니다.
2. **제외 규칙 즉시 취소**:
   - 현재 `.crexignore` 규칙과 일치하는 지적 항목에는 `[제외됨]` 배지와 `[취소]` 버튼이 표시됩니다.
   - `[취소]` 버튼을 누르면 해당 규칙 줄이 `.crexignore`에서 안전하게 제거됩니다.
3. **저장소 규칙 일괄 관리**:
   - 판정 내역 상단 툴바의 `[.crexignore 관리]` 버튼을 누르면 현재 저장소에 등록된 모든 규칙을 한눈에 조회하고, 개별 규칙을 삭제하거나 새 패턴을 직접 입력해 추가할 수 있습니다.

## 주의사항

1. **슬래시(`/`) 사용**: Windows 환경이더라도 경로 구분자는 역슬래시(`\`) 대신 슬래시(`/`)를 사용하십시오.
2. **상대 경로 표기**: 모든 경로는 워크스페이스 루트 기준의 상대 경로입니다. 경로 맨 앞에 `/`를 붙이지 마십시오 (예: `/tests` 대신 `tests/**`).
3. **정확한 룰 ID 확인**: 룰 ID는 `rules/taxonomy.toml`에 정의된 식별자입니다. 오타가 있으면 매칭되지 않으므로 정확한 룰 ID 또는 와일드카드(`cpp.*` 등)를 사용하십시오.
4. **기각 사유 확인**: 제외 규칙에 의해 걸러진 지적은 JSON/HTML 리포트에서 기각 사유가 `룰 제외(rule_excluded)`로 기록됩니다.
