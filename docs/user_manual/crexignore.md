# 리뷰 대상 제외 (.crexignore)

리뷰 대상 저장소에서 특정 파일·디렉터리를 제외하거나, 불필요한 룰(또는 특정 경로에 한정한 룰)을 리뷰에서 제외하는 방법을 설명합니다.

저장소 루트에 `.crexignore` 파일을 두면, 코드 리뷰 시 검사하지 않을 파일 경로와 제외할 룰을 선언할 수 있습니다.

---

## 언제 쓰나

1. **외부 라이브러리 및 생성된 코드 제외**: `vendor/`, `third_party/`, protobuf 생성 코드(`*.pb.cc`) 등 사람이 직접 작성하지 않은 코드를 건너뛰어 LLM 토큰 비용과 리뷰 시간을 절약합니다.
2. **테스트/문서 코드에서 특정 룰 제외**: 테스트 코드(`tests/**`)에서는 매직 넘버 검사(`any.magic-number`)나 엄격한 예외 처리 룰이 불필요할 수 있습니다. 이럴 때 특정 디렉터리에 한해 룰을 끕니다.
3. **팀 정책과 맞지 않는 룰 전역 제외**: 특정 룰이 현재 프로젝트 표준과 맞지 않거나 오탐이 잦은 경우, 저장소 전체에서 해당 룰을 비활성화합니다.
4. **저장소별 독립된 설정 관리**: `crex.json` 설정을 건드리지 않고 대상 저장소 자체에 `.crexignore` 를 커밋해 두면, 저장소를 리뷰하는 모든 팀원에게 동일한 제외 규칙이 자동으로 적용됩니다.

---

## 파일 위치와 기본 형식

`.crexignore` 파일은 **리뷰 대상 저장소(workspace)의 루트 디렉터리**(`.git` 디렉터리가 있는 위치)에 둡니다.

- 한 줄에 하나의 패턴을 적습니다.
- `#` 으로 시작하는 줄은 주석으로 처리됩니다.
- 빈 줄이나 공백만 있는 줄은 무시됩니다.
- Windows 와 Linux 모두 경로 구분자로 슬래시(`/`)를 사용하십시오.

---

## 1. 파일 및 디렉터리 제외

파일이나 디렉터리 경로 glob 패턴을 적으면, 해당 파일은 리뷰 파이프라인의 시작 단계에서 완전히 제외됩니다.

```gitignore
# 특정 디렉터리 전체 제외
build/
dist/**
third_party/**
vendor/**

# 특정 확장자나 자동 생성 코드 제외
*.pb.h
*.pb.cc
*.min.js
*.generated.cs

# 특정 단일 파일 제외
src/legacy/old_parser.cpp
```

### 동작 방식

- **토큰 비용 절감**: 제외된 파일은 diff 수집 및 청킹(chunking) 단계에서 걸러지므로 LLM 컨텍스트로 전달되지 않습니다.
- **정적분석 시간 단축**: 외부 라이브러리나 빌드 산출물에 대해 불필요한 분석기 실행이 방지됩니다.
- **경로 매칭 규칙**: 모든 경로는 저장소 루트 기준의 상대 경로입니다. 하위 모든 디렉터리를 포함하려면 `디렉터리/**` 형식을 권장합니다.

---

## 2. 전역 룰 제외 (`rule:<룰패턴>`)

특정 룰 ID 또는 와일드카드 패턴 앞에 `rule:` 접두어를 붙이면, 저장소의 모든 파일에서 해당 룰이 리뷰 대상에서 제외됩니다.

```gitignore
# C 스타일 캐스트 룰 전역 제외
rule:cpp.c-style-cast

# C++ 관련 모든 룰 제외
rule:cpp.*

# 매직 넘버 검사 룰 제외
rule:any.magic-number
```

### 동작 원리

1. **생성 모델(Generator) 스키마 제외**: 리뷰 청크를 모델에 전달할 때, 프롬프트에 제공되는 룰 택소노미 스키마에서 해당 룰이 사전에 제거됩니다.
2. **필터 단계 결정론적 기각**: 생성 모델이 혹시 해당 룰로 지적을 생성하더라도, 필터(ReviewFilter) 단계에서 결정론적으로 즉시 기각(`RULE_EXCLUDED`)되며 검증 모델(Verifier)로 넘어가지 않습니다.

---

## 3. 특정 경로에 한정한 룰 제외

특정 디렉터리나 파일에서만 특정 룰을 끄고, 다른 소스 코드에서는 정상적으로 검사하고 싶을 때 사용합니다. 세 가지 작성 방식을 지원합니다.

### 문법 1: 콜론(`:`) 구분

`<경로패턴>:<룰패턴>`

```gitignore
# src/legacy 하위에서는 C++ 관련 모든 룰 제외
src/legacy/**:cpp.*

# tests 하위에서는 매직 넘버 룰 제외
tests/**:any.magic-number
```

### 문법 2: 공백 및 `rule:` 접두어

`<경로패턴> rule:<룰패턴>`

```gitignore
# tests 하위에서는 매직 넘버 룰 제외
tests/** rule:any.magic-number

# vendor 하위에서는 보안 관련 룰 제외
vendor/** rule:security.*
```

### 문법 3: 콜론 및 `rule:` 접두어

`<경로패턴>:rule:<룰패턴>`

```gitignore
# src/parser 디렉터리에서는 포인터 무효화 룰 제외
src/parser/*:rule:cpp.dangling-*
```

### 동작 방식

- 매칭된 파일(`tests/test_calc.py`)을 리뷰할 때는 `any.magic-number` 룰이 프롬프트에서 제외되고 필터에서 기각됩니다.
- 매칭되지 않은 일반 파일(`src/calc.py`)을 리뷰할 때는 해당 룰이 정상 적용되어 매직 넘버 지적이 발생할 수 있습니다.

---

## 4. `crex.json` 설정과의 관계

`.crexignore` 와 `crex.json` 의 설정은 서로 대체되는 것이 아니라 **합산(union)**되어 적용됩니다.

```json
{
  "review": {
    "exclude": [
      "temp/**"
    ],
    "exclude_rules": [
      "cpp.c-style-cast",
      "src/legacy/**:cpp.*"
    ]
  }
}
```

### 제외 항목의 병합 순서

1. **내장 기본 제외(DEFAULT_EXCLUDE)**: `.git`, `.*`, `*.min.js` 등 기본 무시 패턴
2. **`crex.json` 의 `exclude` / `exclude_rules`**: 도구 설정 파일에 정의된 공통 패턴
3. **`.crexignore`**: 저장소 루트 파일에 정의된 저장소별 패턴

셋 중 하나라도 제외 조건에 부합하면 리뷰 대상에서 빠집니다.

| 설정 위치 | 권장 용도 | 장점 |
|---|---|---|
| `.crexignore` | 저장소 루트 (`.git` 과 같은 위치) | Git 에 커밋되어 팀 전체에 자동으로 동일한 규칙 적용 |
| `crex.json` | CREX 실행 환경 또는 전역 설정 | 여러 저장소에 공통으로 강제할 인프라/보안 정책 정의 |

## 작성 예시

저장소 루트에 둘 수 있는 완성된 `.crexignore` 예시입니다.

```gitignore
# ==============================================================================
# .crexignore
# ==============================================================================

# 1. 파일/디렉터리 제외 (토큰 절약 및 스캔 제외)
build/**
dist/**
bin/**
obj/**
third_party/**
vendor/**
*.pb.h
*.pb.cc
*.min.js

# 2. 전역 룰 제외 (프로젝트 전체에서 비활성화)
rule:cpp.c-style-cast

# 3. 경로별 한정 룰 제외 (특정 디렉터리에서만 제외)
# 테스트 코드에서는 매직 넘버 검사 제외
tests/**:any.magic-number

# 레거시 폴더에서는 C++ 관련 룰 전체 제외
src/legacy/**:cpp.*

# 외부 스크립트에서는 ruff 린트 룰 제외
scripts/vendor/** rule:python.*
```

## 주의사항

1. **슬래시 사용**: Windows 환경이라도 역슬래시(`\`) 대신 슬래시(`/`)를 사용하십시오.
2. **상대 경로**: 모든 경로는 워크스페이스 루트 기준의 상대 경로입니다. 경로 앞에 `/` 를 붙이지 마십시오 (예: `/tests` 대신 `tests/**`).
3. **룰 ID 확인**: 룰 ID는 `rules/taxonomy.toml` 에 정의된 식별자입니다. 오타가 있으면 제외되지 않으므로 정확한 식별자 또는 와일드카드(`cpp.*` 등)를 사용하십시오.
4. **리포트 확인**: 제외된 지적은 리포트에서 `기각 사유: 룰 제외(RULE_EXCLUDED)`로 집계됩니다.
