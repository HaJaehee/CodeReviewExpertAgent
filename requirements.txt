#  CREX 런타임 의존성
#
#  ## 코어는 이것들이 없어도 돌아간다
#
#  청킹·생성·검증·리포트·평가 하네스와 `python -m crex review|scan|doctor` 는
#  전부 표준 라이브러리만 쓴다. 아래는 **MCP 서버(Zed 연동)** 를 위한 것이다.
#
#      python tests/run_all.py     # 의존성 없이 전부 통과해야 한다
#      python -m crex review        # 의존성 없이 동작한다
#      python -m crex.mcp           # fastmcp 필요
#
#  이 구분을 유지하는 이유: 폐쇄망 반입 직후 무결성 확인이 pip install 을
#  전제하면 곤란하다. 소스만 옮겨도 테스트가 돌아야 한다.
#
#  ## 폐쇄망 반입
#
#  인터넷 되는 장비에서 wheel 을 미리 받는다.
#
#      pip download -r requirements.txt -d wheels/ \
#          --platform win_amd64 --python-version 312 --only-binary=:all:
#
#  폐쇄망에서:
#
#      pip install --no-index --find-links wheels/ -r requirements.txt
#
#  fastmcp 는 의존성이 적지 않다(pydantic, httpx, mcp 등). `pip download` 가
#  받아오는 wheel 전부를 함께 옮겨야 한다. 보안 검토 대상이 늘어나는 만큼,
#  MCP 연동이 실제로 필요한 장비에만 설치하는 것을 권한다.

# MCP 서버 — 프로토콜 처리, 타입 힌트/docstring 에서 도구 스키마 자동 생성
#
#   stdio 전송만 쓸 것이면 2.0 으로도 충분하다. Streamable HTTP
#   (`python -m crex.mcp --transport http`) 는 2.3 부터 있고, 전송 이름이
#   2.9 에서 "streamable-http" → "http" 로 바뀌었다. crex/mcp.py 가 둘 다 받는다.
fastmcp>=2.3

# git 접근 — 없으면 subprocess 폴백으로 동작한다 (crex/gitio.py)
GitPython>=3.1.40
